MCPについて2 - MCPの仕組み(2025/10版)

はじめに

前回の資料では、MCPの概要と活用シーンについて紹介しました。今回は、MCPがどのような仕組みで動作し、AIエージェントがどのようにMCPを通じて様々なツールやサービスを利用できるようになっているのかについて解説します。MCPサーバーやクライアントを自作する際にも必要となる観点となります。

MCPサーバー

MCPサーバーは、具体的なサービスの機能をMCP形式で公開します。リソース・ツール・プロンプトの3つの要素を組み合わせて、AIエージェントに統合的な機能を提供します。

主な機能

  • 要素定義の公開: リソース、ツール、プロンプトの名前、説明、パラメータ情報を提供
  • リクエスト処理: クライアントからのアクセス・実行要求を受け付け
  • 処理の実行: 実際の処理を実行（データ取得、操作実行、プロンプト提供など）
  • 結果の返却: 実行結果を標準化された形式でクライアントに返す

定義の重要性

MCPサーバーは、各要素をAIが理解できる形式で定義します。これには以下の情報が含まれます：

  • 名前: 要素の識別子
  • 説明: 要素が何をするかの自然言語での説明
  • パラメータ: 必要な入力情報と型定義
  • 戻り値: 期待される出力の形式

この定義により、AIエージェントは「どの要素をどう使えばよいか」を自律的に判断できます。

MCPが提供する3つの基本要素

MCPサーバーは、AIエージェントに対して以下の3つの基本要素を提供します：

1. Resources（リソース）

データソースへのアクセスを提供します。ファイルの内容、データベースのレコード、APIからのデータなど、AIが読み取ることができる情報源です。

  • 例：テキストファイル、画像、データベースの内容、Webページの情報
  • AIはリソースを参照して、文脈に基づいた回答を生成できます

2. Tools（ツール）

AIが実行できる操作・機能を提供します。AIは状況に応じて適切なツールを選択し、実行することができます。

  • 例：データベースへのクエリ実行、ファイルの作成・編集、APIの呼び出し
  • AIは複数のツールを組み合わせて複雑なタスクを実行できます

3. Prompts（プロンプト）

事前定義されたプロンプトテンプレートを提供します。特定のタスクや質問のための構造化された指示です。

  • 例：コードレビュー用のプロンプト、文書要約用のプロンプト
  • ユーザーや開発者が一貫性のある結果を得るための標準化された方法

AIエージェントによる利用

AIエージェントは、MCPクライアントを通じて以下のように動作します：

  1. ユーザーからの指示を受け取る
  2. MCPクライアントに利用可能なリソース・ツール・プロンプトを問い合わせる
  3. 指示を実行するために必要な要素を選択
  4. MCPクライアント経由で要素にアクセス・実行
  5. 実行結果を解釈し、ユーザーに返答

MCPクライアント

MCPクライアントは、ホストアプリケーション内で動作し、MCPサーバーと通信するためのインターフェースです。各クライアントは特定のMCPサーバーと1:1の関係を持ちます。

主な機能

  • サーバー接続管理: MCPサーバーとの接続を確立・維持
  • リソース・ツール・プロンプトの取得: サーバーが提供する要素の一覧を取得
  • リクエスト送信: ユーザーの指示に基づいて適切な要素を呼び出す
  • レスポンス処理: サーバーからの結果を受け取り、ホスト（AIモデル）に渡す

通信の流れ

[ユーザー] → [ホスト（LLMアプリ）] → [MCPクライアント] → [MCPサーバー] → [実際のサービス]
                      ↑                                                                         ↓
                      └────────────────── 結果の受け取りと解釈 ─────────────────┘

AIエージェントがMCPを利用する具体的な流れ

ステップ1: 初期化と機能ネゴシエーション

AIアプリケーション（ホスト）起動時、MCPクライアントは設定された各MCPサーバーに接続します。

  • initializeメッセージを送信し、プロトコルバージョンを確認
  • クライアントとサーバーがサポートする機能を交換
  • 互換性を確認してセッションを確立

ステップ2: 利用可能な要素の発見

接続が確立されると、クライアントは各サーバーから以下を取得します：

  • resources/list: 参照可能なデータソース
  • tools/list: 実行可能なツール
  • prompts/list: 利用可能なプロンプトテンプレート

これらの情報は、AIエージェントが利用できる「能力」として認識されます。

ステップ3: ユーザー指示の解釈

ユーザーから指示を受け取ると、AIエージェントは：

  1. 指示の内容を分析
  2. 必要なリソース・ツールを特定
  3. 実行順序を計画

ステップ4: リソースへのアクセスとツールの実行

AIエージェントはMCPクライアント経由でリソースにアクセスし、ツールを実行します：

リソースの読み取り例：

{ "jsonrpc": "2.0", "method": "resources/read", "params": { "uri": "file:///project/config.json" } }

ツールの実行例：

{ "jsonrpc": "2.0", "method": "tools/call", "params": { "name": "database_query", "arguments": { "query": "SELECT * FROM users WHERE active = true" } } }

このように、AIエージェントは必要に応じてリソースにアクセスし、ツールを実行することで、ユーザーの指示を実現します。サーバーからの応答を受け取った後、AIエージェントは結果を解釈して次のアクションを決定し、必要に応じてさらに別のリソースを参照したり、ツールを呼び出すこともあります。

セキュリティと権限管理

MCPは、セキュリティを考慮した設計になっています：

アクセス制御

  • ツールごとに実行権限を設定可能
  • ユーザーの承認が必要な操作を定義可能

データ保護

  • 通信の暗号化をサポート
  • 機密情報の扱いに関する制御機能

監査とログ

  • ツールの実行履歴を記録
  • 問題発生時のトレーサビリティを確保

まとめ

MCPは、標準化されたプロトコルにより、AIエージェントが様々なツールやサービスを統一的な方法で利用できる仕組みを提供しています。

MCPの価値

  • Resources（リソース）、Tools（ツール）、Prompts（プロンプト）の3つの要素を通じて、AIエージェントは外部システムと柔軟に連携
  • AIエージェントは、利用可能な要素を自律的に発見し、その説明から適切な使い方を理解できる
  • 複数のリソースとツールを組み合わせて複雑なタスクを実行できる

この仕組みにより、AIエージェントは真の意味での「エージェント」として、ユーザーの意図を理解し、最適な方法でタスクを実行できるようになるのです。
