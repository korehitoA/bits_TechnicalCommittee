「にゃんこ大戦争」がAWSからGoogle Cloudへ移行
～ 無停止運営を実現したインフラ戦略 ～

概要

スマートフォン向けアプリケーション「にゃんこ大戦争」を開発・運営する株式会社ポノスが、サービスのITインフラをAWSからGoogle Cloudへ移行するプロジェクトを実施しました。この移行は、サービスの無停止運営にかかる手間やコストを削減するための戦略的な取り組みでした。

ITインフラ移行プロジェクト

移行の背景と課題

ポノスが「にゃんこ大戦争」の運営において直面していた主要な課題は以下の通りです。

移行の背景となった課題：
  • Amazon Aurora※1で発生するダウンタイム
  • 無停止での運営を最優先事項としているため、メンテナンス対応の負担が大きい

AWS都合のメンテナンスが年に数回発生し、約数秒のダウンタイムが生じていました。Amazon Auroraでダウンタイムが発生する度に、無停止運営を維持するための手間やコストが発生していました。

Google Cloudを選択した理由

ポノスが移行先としてGoogle Cloudを選択した決定的な理由は以下の通りです。

Google Cloud選択の理由：
  • DBのダウンタイムが発生しない
  • Cloud Spanner※2は、メンテナンスによるダウンタイムが発生しない設計

この技術的優位性により、無停止運営を継続する保守作業のコスト削減が狙えます。

移行プロジェクトの実施

ポノスは、明確な目的を掲げてITインフラ移行プロジェクトを立ち上げました。

プロジェクトの目的：
  • 無停止運営のための手間とコストの削減
  • 保守作業の時間を減らし、開発に携わる時間を増やす

プロジェクトは2023年夏に発足し、2025年1月に移行作業が完了しました。

※1 Amazon Aurora…AWSが提供するリレーショナルデータベース（RDB）サービス。

※2 Cloud Spanner…Google Cloudが提供するリレーショナルデータベース（RDB）サービス。NewSQL（後述）サービスの一つ。

まとめ

ポノスの「にゃんこ大戦争」におけるインフラ移行事例は、明確な目的意識に基づいた戦略的な取り組みです。DBダウンタイムの排除と無停止運営の実現という具体的な課題に対して、適切な技術選択により解決策を見出しました。

この事例は、クラウドサービス間でのITインフラ移行においても、サービスの特徴を十分に比較検討することの重要性を示しています。クラウドサービス間の技術的な違いに着目したITインフラ移行により、保守作業のコスト削減、開発への集中という2つのメリットが生まれた成功事例と言えるでしょう。

補足：Cloud Spannerに使用されるDB言語 - NewSQLとは -

Google CloudのCloud Spannerは、「NewSQL」と呼ばれる比較的新しいデータベース言語を用いたサービスです。NewSQLは、従来のSQLとNoSQLの長所を組み合わせた言語として登場しました。
