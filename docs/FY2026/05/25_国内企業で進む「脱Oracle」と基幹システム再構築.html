国内企業で進む「脱Oracle」と
基幹システム再構築

〜 コスト・ロックイン問題からAIネイティブ移行まで 〜

■ はじめに

かつて基幹システムのデータベースといえば「Oracle Database（以下、Oracle DB）」が事実上の標準とされていました。しかし近年、コストやDX推進を背景に「脱Oracle」という言葉が企業のIT戦略会議で公然と語られるようになっています。

この流れは今後の案件・技術動向にも直結するため、SEとして背景・手法・業界の動きを押さえておくことが重要です。

現在のトレンド：
単なるDB移行ではなく、「クラウド化」「AI活用」「運用自動化」を含めた"基幹システム全体のモダナイゼーション"が主流になりつつあります。

■ 1. 「Oracle依存」をどう減らすか

背景 ― なぜ今「脱Oracle」なのか

「脱Oracle」が起きている主な理由は2つです。

① コスト高騰とベンダーロックイン

Oracle DBはCPUコア数や利用機能に応じてライセンス費用が増加する複雑な体系です。 年間保守費だけでライセンス費用の20％前後に達するケースも珍しくありません。

また、一度Oracle前提で構築した基幹システムは他DBへの移行難易度が高く、長期的なロックインが発生しやすい構造となっています。

② クラウドネイティブとの相性

マイクロサービス・コンテナ・従量課金を前提とするクラウドネイティブ設計と、Oracleのライセンス体系は相性が良いとは言えません。

クラウド移行後もコストメリットが出にくいことから、PostgreSQL系サービスへ切り替える企業が増加しています。

取り組みの実態 ― 段階的なハイブリッド戦略が主流

大企業の基幹システムは長い歴史を持つため、一気に切り替えるのは現実的ではありません。現在の主流は「段階的移行」です。

Oracle環境の整理
→
仮想化・クラウドリフト
→
DB置き換え
→
AI活用基盤へ統合
  • 新規開発・更改案件は PostgreSQL や SQL Server などオープン技術へ切り替え
  • Oracle依存の強いシステムは Nutanix 等で効率化し、段階的にクラウド化
  • Azure・AWS を中心に再設計し、将来的な脱却を見据えた構成へ

主な移行事例

企業 概要 ポイント
ベネッセコーポレーション 約350システムの7割をAzureへ移行 Oracle DBからSQL Serverへ移行し、年間ITコストを約2割削減
田辺ファーマ 段階的クラウド移行を推進 Oracle依存度に応じてAzure移行とNutanix活用を使い分け
Amazon（海外事例） 75PBのデータをAWSへ移行 Aurora・DynamoDB・Redshiftによる超大規模基盤を実現

■ 2. 移行先として選ばれているDB

主な移行先

現在、移行先として最も多く選ばれているのは PostgreSQL 系です。 OSSであることに加え、AWS・Azure・Google Cloud すべてがマネージドサービスを提供しているため、クラウドとの親和性が高い点が評価されています。

移行先DB 特徴 主な用途
PostgreSQL OSS・高機能・クラウド対応 基幹システム全般
SQL Server / Azure SQL Microsoft製品との統合性 Azure中心企業
Amazon Aurora 高性能マネージドDB 大規模Web/OLTP
BigQuery / Redshift 分析・DWH特化 BI・AI分析基盤

移行における最大の課題

DBの移行自体は変換ツールで一定自動化できますが、最大の難所はアプリケーション改修です。

主な改修ポイント：
  • Oracle独自SQL（ROWNUM / CONNECT BY / DECODE 等）の書き換え
  • PL/SQL ストアドプロシージャの移植
  • バッチ処理・トランザクション制御の再設計
  • 「Oracle特有の挙動」に依存したコードの洗い出し
多くのSIerでは事前アセスメントとPoC（概念実証）を必須工程として位置づけています。

■ 3. 日立によるOracle基幹システムのクラウド移行支援

サービスが生まれた背景と目的

Oracle DBを使った基幹システムのクラウド移行は、大規模かつミッションクリティカルなシステムが多く、高度なノウハウが必要とされます。

こうした背景を受け、日立製作所は2025年3月に「クラウド移行支援サービス for Oracle Database」を提供開始しました。

サービスの狙い：
単なるDB移行ではなく、AI活用を前提としたモダナイゼーション基盤へ再構築すること。「Lumada」戦略の一環として位置づけられています。

サービスの概要と最新動向

項目 内容
クラウド対応 Oracle Database@AWS に対応し、Azure / AWS の両方へ移行可能
共同検証 日立・日本オラクル・AWSの連携で移行コスト30%削減、期間2か月短縮を実証
AI活用 基幹DBとAI分析用DBを分離し、リアルタイム分析基盤を提供

SEに求められるスキルの変化

DBスキル

PostgreSQL / SQL Server / Aurora 等の設計・移行知識

クラウドスキル

AWS / Azure のマネージドDB・IaC・運用自動化

AI基盤理解

データ連携・分析基盤・RAG向けデータ構造理解

標準化・テンプレート化が進む一方で、「DB」「クラウド」「AI基盤」を横断して理解できるSEの価値はさらに高まっていくと考えられます。
